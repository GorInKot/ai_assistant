# Ассистент как раздел портала

Ассистент открывается плиткой «ИИ-ассистент» на главной странице корпоративного портала
(`portalrnsk`, Django) — внутри портала, без второго входа. Вторая плитка, «Конструктор и
чертежи» (`/assistant/tools/`), открывает раздел ассистента `/tools` по тому же пропуску. Файлы портала не меняются:
надстройка `portal_bridge` подключается при запуске через `DJANGO_SETTINGS_MODULE`.

## Как это работает

1. Пользователь входит в портал и нажимает плитку «ИИ-ассистент» (`/assistant/`).
2. Портал выдаёт одноразовый пропуск на 60 секунд: логин, ФИО, роль; подпись — HMAC-SHA256
   общим секретом. Пропуск уходит POST-запросом прямо в окно ассистента (iframe) — в адресную
   строку и журналы не попадает.
3. Ассистент (`POST /sso/portal`) проверяет подпись, срок и одноразовость, находит или заводит
   пользователя `<логин>@portal.local` и открывает чат — или раздел из поля `next` формы, если он
   в списке разрешённых (`/`, `/tools`); иначе тоже чат.

Роль берётся из портала при каждом входе: «Админ» → admin, «Руководитель» → manager, остальные —
user. Пропуском нельзя войти в учётную запись, заведённую в ассистенте напрямую, а адреса
`@portal.local` нельзя зарегистрировать. Встраивать ассистент в iframe разрешено только порталу
(`frame-ancestors` из `PORTAL_ORIGINS`).

## Кнопка ассистента на всех страницах

На каждой странице портала для вошедшего пользователя — круглая кнопка в правом нижнем углу (цвета
портала). Она открывает справа панель ~420 px (на узком экране — на весь экран) с компактным
ассистентом; полная версия остаётся плиткой. Кнопки нет на странице входа и на странице самого
ассистента, а внутри фреймов (дашборды) она не показывается.

1. `portal_bridge/asgi.py` оборачивает всё приложение портала (Django и СИЗ) и дописывает перед
   `</body>` HTML-страниц вошедших пользователей одну строку — скрипт `widget.js` ассистента.
   Ответы не 200, не HTML, сжатые и фрагменты без `</body>` не трогаются; если строка уже есть
   (`data-ai-assistant-widget`), вторая не добавляется. Выключить — `ASSISTANT_WIDGET=0`.
2. `widget.js` (без сторонних библиотек, `frontend/public/widget.js` ассистента) рисует кнопку
   в изолированном Shadow DOM — стили портала и кнопки не мешают друг другу.
3. При открытии панель загружает `/assistant/panel/` портала: портал выдаёт одноразовый пропуск,
   и окно сразу переходит в ассистент на `/widget`. Пропуск выдаётся при каждой загрузке панели,
   поэтому в панели всегда тот, кто вошёл в портал (важно на общих терминалах).
4. Открыта панель или закрыта — помнится в пределах вкладки браузера: после перехода на другую
   страницу она открывается сразу, с той же беседой.
5. Панель и страница обмениваются сообщениями только между адресами портала и ассистента:
   `widget.js` принимает их только от адреса ассистента и только из своей панели; ассистент
   запоминает адрес портала при входе панели, только если он есть в `PORTAL_ORIGINS`. «✕» закрывает
   панель, «Открыть полностью ↗» открывает плитку «ИИ-ассистент» в новой вкладке на той же беседе.

## Поручения из записи IVA

В демо-портале надстройка добавляет кнопку «🎙 Запись совещания» в панель действий раздела
«Протокол» (`/protocol/`) и доску `/tasks/`. Кнопка доступна пользователям с правом
редактирования и сразу открывает выбор файла. После выбора запись загружается автоматически;
обработка, проверка стенограммы и подтверждение поручений проходят в окне на той же странице.
Прежний адрес `/protocol/meeting/` перенаправляет в «Протокол» с открытым окном загрузки.
После загрузки MP4, MOV, M4A, MP3 или WAV (до 350 МБ) запись обрабатывается в фоне:
`ffmpeg` делает WAV,
`whisper-cli` распознаёт русскую речь, локальная LLM предлагает поручения со ссылками на
временные метки. Вместо записи можно загрузить TXT, SRT или VTT стенограммы (до 2 МБ).
Стенограмма и черновики показываются для проверки; в «Протокол» записываются только
отмеченные и подтверждённые человеком пункты. «Панель задач» показывает эти же пункты по
статусу, без второй базы данных. Повторное подтверждение одной записи не добавляет дубли.

Для локального распознавания на macOS: установить `ffmpeg` и `whisper.cpp` с `whisper-cli`;
скачать многоязычную модель `ggml-small.bin` из официального каталога моделей whisper.cpp
в `tools/meeting/ggml-small.bin` или указать `MEETING_WHISPER_MODEL`. Для извлечения поручений
запустить локальный Ollama с моделью из `MEETING_LLM_MODEL` (по умолчанию `ministral-3:3b`)
и OpenAI-совместимым адресом `MEETING_LLM_BASE_URL` (по умолчанию
`http://127.0.0.1:11434/v1`). Для этого сценария допускается только адрес на той же машине;
записи и стенограммы не отправляются в облачную LLM. Эти переменные задаются в
`integrations/portal/env.sh`; образец — `env.example.sh`.

Файлы встречи хранятся в `PORTAL_DATA_DIR/media/meeting_jobs/`; удаление и срок хранения
нужно определить перед использованием на рабочих совещаниях. Реальные данные портала и
записи IVA не входят в git.

Синтетический образец для показа: `sh scripts/create_iva_demo.sh` создаёт
`samples/iva_demo.mp4` по тексту `demo/iva_meeting_script.txt` системным голосом macOS.
После выбора в «Протоколе» он проходит тем же путём, что запись IVA; на выступлении его следует
представлять как демонстрационный образец, а не как запись рабочего совещания.

### Подключение в настоящем портале

Портал коллег — без надстройки — подключает кнопку одной строкой в `templates/base.html` перед
`</body>`:

```django
{% if user.is_authenticated and request.resolver_match.url_name != "assistant" %}<script src="https://АДРЕС-АССИСТЕНТА/widget.js" data-panel="{% url 'assistant_panel' %}" data-full="{% url 'assistant' %}" data-ai-assistant-widget defer></script>{% endif %}
```

Для этого в портале должны быть страницы ассистента из надстройки: `assistant`, `assistant_tools`
и `assistant_panel` (`portal_bridge/views.py`, шаблоны `assistant/index.html` и
`assistant/panel.html`, адреса — как в `portal_bridge/urls.py`) и общий секрет
`ASSISTANT_SSO_SECRET`. В `.env` ассистента — адрес портала в `PORTAL_ORIGINS`.

Страницы СИЗ отдаёт отдельное приложение (не `base.html`): либо та же строка без тегов Django
(`<script src="https://АДРЕС-АССИСТЕНТА/widget.js" data-panel="/assistant/panel/" data-full="/assistant/"
data-ai-assistant-widget defer></script>`) в его `static/index.html`, либо обёртка
`WidgetInjector` из `portal_bridge/widget_inject.py` вокруг `application` в `portalrnsk/asgi.py` —
тогда строка в `base.html` не нужна вовсе.

## Что входит

| Файл | Назначение |
|---|---|
| `portal_bridge/settings.py` | настройки портала как есть + раздел ассистента; данные демо-портала — в `.data/` |
| `portal_bridge/urls.py` | адреса портала как есть + `/assistant/`, `/assistant/tools/`, `/assistant/panel/` |
| `portal_bridge/views.py` | плитки на главной, страницы с окном ассистента и содержимое панели |
| `portal_bridge/sso_pass.py` | пропуск (без Django; формат сверяется тестом `tests/test_portal_sso.py`) |
| `portal_bridge/widget_inject.py` | вставка кнопки в HTML-ответы (без Django; тесты — `tests/test_portal_widget.py`) |
| `portal_bridge/asgi.py` | приложение портала как есть + кнопка; кто вошёл — по сессии Django |
| `run_portal.sh` | миграции демо-базы и запуск портала (`portal_bridge.asgi`) на `127.0.0.1:8080` |

## Запуск на Mac

```sh
# портал: окружение Python 3.12 в его папке (один раз)
python3.12 -m venv ../PROJFORTERMINAL/.venv
../PROJFORTERMINAL/.venv/bin/pip install "Django>=4.2,<5.0" Pillow fastapi "uvicorn[standard]" \
    openpyxl python-multipart xlrd lxml python-docx

# общий секрет: integrations/portal/env.sh (ASSISTANT_SSO_SECRET) и .env ассистента:
#   PORTAL_SSO_SECRET=<тот же секрет>
#   PORTAL_ORIGINS=http://127.0.0.1:8080 http://localhost:8080
cp integrations/portal/env.example.sh integrations/portal/env.sh

integrations/portal/run_portal.sh          # портал: http://127.0.0.1:8080
myenv/bin/python -m uvicorn app.main:app   # ассистент: http://127.0.0.1:8000
```

Администратор демо-портала: `PYTHONPATH=integrations/portal:../PROJFORTERMINAL
DJANGO_SETTINGS_MODULE=portal_bridge.settings PORTAL_DATA_DIR=integrations/portal/.data
../PROJFORTERMINAL/.venv/bin/python ../PROJFORTERMINAL/manage.py createsuperuser`.

## Перенос в сам портал

Когда раздел войдёт в портал штатно: `views.assistant` и шаблон `assistant/index.html` — в
портал, плитку — в список `panels` в `portalrnsk/views.py`, модуль `assistant` — в
`ModuleAccess.MODULE_CHOICES` (тогда доступ к разделу настраивается в админке по ролям).
